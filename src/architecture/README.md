# 架构全景——代码跑在哪、怎么通信、怎么部署

本目录回答 Web 开发的根本问题：**你写的代码到底在哪里运行？它们之间怎么连接？从编辑器里的文件到用户屏幕上的页面，中间发生了什么？**

## 为什么需要这个目录

其他文档在讨论 React vs Vue、Django vs FastAPI 之前，你需要先理解一个更基本的东西——**这些技术的运行时的物理位置和通信方式**。

把 Web 开发理解为一栋建筑：

| 本目录 | 其他文档 |
|--------|---------|
| 这栋楼的地基、承重墙、管道线路——物理骨架 | `domains/` 讲每个房间内部的装修方案 |
| 讲"Nginx 在这栋楼的入口处，所有访客经过它" | `domains/backend.md` 讲"后端房间里发生了什么" |
| 讲"前端代码从设计师电脑到了访客手机里" | `domains/frontend.md` 讲"前端房间里的家具怎么摆" |

**先把这个目录读完，再看其他文档。** 否则你会在不知道"代码跑在哪"的情况下讨论"这个框架好还是那个框架好"。

## 读完你会知道

- 前端代码不在服务器上跑——在用户的浏览器里跑，任何人都能看到你的源码
- "服务器"不是一个黑盒——它上面跑着 Nginx（入口）、Node.js/Go 进程（业务）、PostgreSQL（数据），各占一个端口
- "部署"不是魔法——是把编译产物复制到服务器，然后启动一个进程
- 为什么需要 Nginx——不是"最佳实践"，是物理现实决定的（公网只有一个 80 端口）
- 技术选型不是选"最好的"——是在你的约束下选"trade-off 最划算的"

